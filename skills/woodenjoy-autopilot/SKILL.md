# 우드엔조이 오토파일럿

사용자가 "이번 글 준비해줘", "네이버 글 써줘(한 번에)"라고 하거나 예약 실행이 들어오면 아래를 끝까지 진행한다. 중간에 묻지 않는다. 목표는 후킹·유입·검색 노출이고, 그보다 앞서는 조건은 내용이 사실이고 이미지가 정확한 것이다. 사용자에게는 항상 한국어로 보고한다.

## 준비
1. GitHub 저장소 `woodenjoy-autopilot`을 가져온다. `AUTOPILOT.md`를 읽고 그 순서를 따른다 (아래는 요약, 다르면 AUTOPILOT.md 우선)
2. `config/settings.json`, `config/terms.json`, `topics/used.json`, `topics/backlog.md`, `topics/experience.md`, `topics/performance.md`를 읽는다
3. `npm install`, `pip install -r requirements.txt`(필요하면 `--break-system-packages`), 한글 글꼴(Noto Sans CJK KR) 확인
4. 글 폴더 이름의 날짜는 다음 네이버 업로드일(settings.json `slots.naver`의 다음 요일)

## 단계
1. **제목 선정**: backlog에서 안 쓴 후보 5개 → 계절·최근 검색 수요를 웹에서 확인 → 구글 상위 글 제목과 쇼핑몰 상품명 용어 확인 → naver-woodenjoy-post 스킬 제목 공식으로 5안. 소비자 용어만, 확인 안 된 말은 쓰지 않고 terms.json에 기록
   - 이미 쓴 글과 같은 질문이면 새 글 대신 기존 글 보완을 제안한다
   - 제목에 "무조건·완벽 정리·BEST·가장 쉬운·상위 노출" 같은 근거 없는 강도 금지. 후킹은 독자 상황과 구체적 기준으로
2. **브리프**: `post.json`의 `brief`에 reader / question / answer / out_of_scope / next_action을 먼저 적고, 제목은 이 범위 안에서만 약속한다
3. **글**: naver-woodenjoy-post 스킬 규칙으로 `naver.md` 작성 (2,000~3,500자, 표시 형식은 AUTOPILOT.md 2단계). 분량·키워드 횟수를 채우려고 반복하지 않는다
   - 경험담("현장에서 보면" 등)은 `topics/experience.md`에 `- 확인: 사장님` 줄이 있는 기록만 쓰고 `experience_used`에 번호를 적는다. 기록이 없으면 새 E번호를 "사장님 확인 대기"로 만들고 승인 요청에서 묻는다. 경험을 지어내지 않는다
   - 숫자·규격·가격·비교·원인 설명은 근거가 있는 것만. 근거가 없으면 문장을 뺀다
4. **이미지**: `cards.json`(6~8장, 장마다 새 정보 + 다른 형태의 그림, 구조 그림은 도형으로 직접) → `node tools/render_cards.js posts/<폴더>`
5. **글 점검**: `python3 tools/check_text.py posts/<폴더>` 통과 (브리프, 과장 표현, 작업 메모, 확인 안 된 경험담, 키워드 반복, 네이버 업로드 형식 포함) + 제목 약속·사실 근거·카드와 글 일치를 직접 다시 읽기
6. **이미지 점검**: 자동 점검 통과 후 card-image-check 스킬로 전체보기와 장마다 눈으로 확인
7. **인스타**: 첫 줄 60자 이하 훅, 해시태그 5개 이하, 링크 금지, "프로필 링크의 블로그" 안내
8. **스레드**: 본문 + 댓글 2개, 각 500자 이하, 링크는 마지막 댓글에만 `[네이버 글 링크]`
9. **고치기**: 5·6단계 실패 시 고치고 다시, 최대 3번. 그래도 실패하면 status는 draft로 두고 실패 내용을 보고
10. **승인 요청**: status를 ready로 → 브랜치 `post/<폴더>`에 커밋(카드 포함) → PR `[승인 대기] <제목>`. 본문에 `python3 tools/schedule.py show posts/<폴더>` 결과(업로드 예정 시간)와 확인 대기 중인 경험 문장을 넣는다. PR이 열리면 GitHub가 다시 점검하고, `naver.via`가 uplika면 네이버에 **비공개**로 올린다
   - GitHub를 쓸 수 없고 이 대화에 uplika 커넥터가 있으면: `python3 tools/naver_markdown.py`로 바꾼 본문과 카드를 uplika 커넥터로 비공개 업로드 (먼저 크롬 확장 켜짐 확인, 카테고리 필수, layout as-is, 이미지 줄 끝 {.ai})
   - 둘 다 없으면: 네이버 원고·카드 이미지·캡션·스레드 문구를 파일로 보낸다
11. **알림**: 제목, 점검 결과, 업로드 예정 시간, 확인이 필요한 경험 문장, 할 일(네이버 앱에서 비공개 글 확인 → PR 병합 → 네이버는 추천 시간에 직접 공개 전환, 인스타·스레드는 정해진 시간에 자동)

## 업로드 시간
- 시간표는 `config/settings.json`의 `slots`(한국 시간). 기본: 네이버 월·수·금 07:00, 스레드 12:30, 인스타 21:00
- GitHub `업로드` 워크플로가 30분마다 `tools/schedule.py due`로 차례가 된 플랫폼만 올린다. 이 스킬에서 직접 시간을 정해 올리지 않는다
- 자동 모드에서 스레드는 네이버 공개 주소가 생긴 뒤 올라간다. 3시간 넘게 놓친 시간은 다음 차례로 미룬다

## 발행 후 (한 달에 한 번, 사용자가 통계를 보여줄 때)
- `topics/performance.md`에 확인한 값만 적는다. 외부 '블로그 지수'는 네이버 공식 점수가 아니므로 근거로 쓰지 않는다
- 예상 검색어와 실제 유입 검색어가 다른 글은 보완 후보. 한 번에 한 가지만 고치고 날짜·이유를 남긴다
- 발행·수정 후 24시간 안에 검색에 안 보인다고 제목을 바꾸거나 다시 올리지 않는다
- 시간대별 조회수로 `slots`를 조정한다 (한 번에 한 플랫폼, 1시간 단위, 근거 숫자를 커밋 메시지에)

## 지킬 것
- 네이버는 uplika 크롬 확장을 통해서만 올린다. 사용자 비밀번호를 다루거나 다른 방법으로 로그인하지 않는다
- 자동 모드(auto_publish true) 전에는 네이버를 항상 비공개로 올린다. 하루에 여러 편 몰아 올리거나 같은 글을 다시 올리지 않는다 (주 3회). 업로드 실패는 자동 재시도하지 않는다
- 토큰·API 키는 GitHub Secrets에만 있다. 이 스킬에서 다루거나 출력하지 않는다
- myinfobay(워드프레스)는 `wordpress_from` 날짜 이후에만, myinfobay-adsense-post 스킬로 네이버와 문장이 겹치지 않게 추가한다
