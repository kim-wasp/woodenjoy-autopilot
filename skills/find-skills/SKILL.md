# Find Skills

오픈 에이전트 스킬 생태계(skills.sh, GitHub)에서 스킬을 찾아 품질을 확인하고, 사용자 계정에 설치하도록 돕는다.
(원본: vercel-labs/skills 의 find-skills. claude.ai 채팅 환경에 맞게 설치 단계를 수정함.)

## 언제 쓰나

- "X 하는 스킬 있어?", "스킬 찾아줘"라고 할 때
- "X 할 수 있어?"인데 X가 전문 작업이라 이미 만들어진 스킬이 있을 법할 때
- 특정 분야(디자인, 블로그 SEO, 자동화, 문서 등) 도움을 원할 때

## 1단계: 필요한 것 파악

1. 분야 (예: 블로그 SEO, 프론트엔드, 문서 처리)
2. 구체적 작업 (예: 제목 짓기, 테스트 작성, PR 리뷰)
3. 흔한 작업이라 스킬이 있을 법한지

## 2단계: 먼저 계정·카탈로그 확인

- 이미 가진 스킬: ListSkills
- 조직/공식 카탈로그: SearchSkills, SuggestSkills
여기서 맞는 게 있으면 그걸 우선 안내한다.

## 3단계: 외부 생태계 검색

- `npx skills find [검색어]`가 실행되는 환경이면 그걸 쓴다.
- 안 되면(네트워크 차단 등) WebSearch / WebFetch로 https://skills.sh/ 리더보드와 검색 결과, GitHub 저장소를 직접 찾는다.
- 자주 쓰이는 출처: `anthropics/skills`, `vercel-labs/agent-skills`, `ComposioHQ/awesome-claude-skills`
- 검색어는 구체적으로("react testing" > "testing"), 안 나오면 동의어로 다시.

## 4단계: 추천 전 품질 검증 (필수)

검색 결과만 보고 추천하지 않는다.
1. 설치 수 — 1K 이상 선호, 100 미만은 주의
2. 출처 신뢰도 — anthropics, vercel-labs, microsoft 등 공식 출처 우선
3. GitHub 스타 — 100 미만 저장소는 의심
4. SKILL.md 내용을 직접 읽고, 수상한 스크립트·외부 전송·과도한 권한 요구가 없는지 확인

## 5단계: 사용자에게 제시

각 후보마다:
1. 스킬 이름과 하는 일 (한국어로 쉽게)
2. 설치 수와 출처
3. 더 볼 수 있는 링크 (실제로 열리는지 확인한 것만)

## 6단계: 설치

사용자가 원하면:
1. GitHub에서 해당 스킬 폴더를 받아(git clone --depth 1) SKILL.md를 끝까지 읽는다.
2. claude.ai 환경에 맞지 않는 부분(로컬 CLI 전용 명령 등)이 있으면 필요한 만큼만 고치고, 고친 점을 한 줄로 알린다.
3. propose_skills 도구로 제안 카드를 띄워 사용자가 저장하게 한다. (`npx skills add -g`는 이 환경에서 계정에 저장되지 않으므로 쓰지 않는다.)
4. 보조 파일(스크립트, 참고 문서)이 꼭 필요한 스킬이면, SKILL.md만으로는 완전히 동작하지 않을 수 있다고 미리 말한다.

## 찾는 게 없을 때

1. 맞는 스킬이 없다고 솔직히 말한다.
2. 지금 바로 직접 도와줄 수 있다고 제안한다.
3. 자주 하는 작업이면 새 스킬로 만들어 주겠다고 제안한다(skill-creator 활용).
