# myinfobay 애드센스 승인용 글쓰기

목표 순서: **① 애드센스 승인 → ② 구글 검색 클릭 → ③ 쿠팡 수익(승인 후)**. 지금은 ①이 최우선이다. 사이트 주제는 "사람 부르기 전에 집에서 해결하는 셀프 집수리·DIY"이며, 필자는 원목가구 제작·시공업체 우드엔조이 운영자다. 같은 주제의 네이버 블로그(cafe_peanut)와 문장이 겹치면 안 된다.

사용자가 "myinfobay 글 써줘: 주제"처럼 한 줄만 말해도 아래 단계를 작성부터 검사·수정까지 끝까지 진행한다. 중간에 묻지 않는다. 이 스킬의 규칙(한국어, 해요체, 승인 기준, 용어 확인, 글 꾸미기)이 다른 블로그 스킬의 기본값보다 우선한다.

## 0. 사전 조사 (가능할 때만)
웹 검색을 쓸 수 있으면 메인 키워드로 구글 상위 글 몇 개를 확인해 다루는 범위, 대략적 분량, 빠진 내용을 파악한다. 규격·기준처럼 사실 확인이 필요한 내용도 이때 확인한다. 쓸 수 없으면 건너뛴다.

## 0-1. 용어 확인 (필수)
업계 용어나 번역어를 그대로 쓰지 않는다. 글에 쓸 부품·공구·자재 이름은 **작성 전에 반드시 웹에서 실제 쓰임을 확인**한다.
- 확인 순서: ① 쇼핑몰 상품명(G마켓·옥션·쿠팡·11번가) ② 철물점·제조사 판매 페이지 ③ 시공·DIY 블로그
- 확인한 용어를 **소비자 용어**(상품명·일반 블로그에서 반복되는 말)와 **업계 용어**(시공자·제조사 자료에만 나오는 말)로 나눈다
- 제목·H2·본문은 소비자 용어가 기본이다. 업계 용어는 처음 나올 때 괄호로 한 번 덧붙인다 (예: "인도어(인셋)"). 구글 검색용으로 영어 용어(full overlay 등)가 필요하면 본문 한 곳에만 괄호로 쓴다
- 쓰임을 확인하지 못한 말은 쓰지 않는다 (예: 일자·반곡·대곡처럼 번역해서 만든 말)
- 이름보다 넓게 쓰이는 제품은 실제 사용처를 밝힌다 (예: 씽크경첩은 옷장·신발장·붙박이장에도 쓰임)
- 쿠팡 후보 표시도 실제 상품명에 쓰이는 검색어로 적는다 (예: `[쿠팡 후보: 씽크경첩 아웃도어 110도]`)

## 1. 승인 기준 (모든 글이 지켜야 함)
- 독창적이고 유용한 내용. 다른 글을 바꿔 쓴 수준이면 "가치가 낮은 콘텐츠"로 거절된다
- 경험 신호: 현장 일화, 실무 판단 기준, 흔한 실수. 사용자가 준 메모를 우선 사용하고 구체적 사건을 지어내지 않는다
- 한 사이트 한 주제: 셀프 집수리·DIY에서 벗어나는 내용 금지
- **승인 전에는 쿠팡 링크를 넣지 않는다.** 대신 `[쿠팡 후보: 제품군]` 표시만 남긴다
- 광고 클릭 유도 문구 금지

## 2. 제목 (구글 검색 결과에서 클릭되게)
3안을 만들고 추천 1개를 고른다. 글 제목은 워드프레스가 자동으로 H1으로 쓰므로 본문에는 H1을 넣지 않는다.
- 핵심 키워드를 앞쪽에, 60자 이내
- 검색 결과에서 눈에 띄는 요소 1개: 구체적 규격(35mm, 6mm), 비용 앵커(출장비 아끼는), 판단 기준(셀프 vs 업체), 연도(2026)
- 제목이 약속한 것은 본문에 반드시 있어야 한다. 과장·낚시 금지

## 3. 본문 구조
1. 도입 2~3문장: 독자 상황 + **결론 먼저**
2. **3줄 요약 박스** (아래 4단계 형식)
3. 목차
4. 질문형 H2 4~6개. 각 H2의 첫 문단은 그것만 읽어도 답이 되게 (AI 개요 인용 대비). H2 안에서 나눌 내용이 있을 때만 H3를 쓴다
5. 비교표 1개 이상 (종류·규격·비용·난이도 등)
6. "현장에서 보면" 팁 박스 1개 이상: 실무 경험, 흔한 실패, 판단 요령
7. 셀프 가능 범위와 업체를 불러야 하는 경계 (주의 박스)
8. 마무리: 요약 3줄 + 관련 글 내부 링크 2~3개 (`[내부링크: 글 제목]`으로 표시)
9. 출처: 사실·기준을 인용했으면 글 끝에 "참고" 한 줄로 링크

분량: 같은 키워드 상위 글 평균의 ±20%를 기준으로, 보통 공백 포함 약 3,000~5,000자. 정의형 짧은 주제는 더 짧아도 된다. 늘리기 위한 반복 금지.

말투: 해요체, 1인칭 실무자 시점. 교과서처럼 매끄럽기만 한 문단은 피하고 구체적인 숫자·규격·상황을 넣는다.

## 4. 글 꾸미기 (사용자가 승인한 디자인)
디자인은 사이트의 추가 CSS(아래 참고)가 담당하므로, 본문에는 색상 코드를 넣지 않고 아래 여섯 가지 형식만 쓴다.
- **표**: 일반 마크다운 표. 워드프레스 표 블록이 되고 CSS가 둥근 모서리·줄무늬 배경을 자동 적용한다. 첫 열은 항목 이름으로 짧게
- **3줄 요약 박스** (도입 바로 다음, 글당 1개):
  `<div class="mi-summary"><strong>3줄 요약</strong><ul><li>…</li><li>…</li><li>…</li></ul></div>`
- **현장 팁 박스** ("현장에서 보면", 글당 1~2개):
  `<div class="mi-tip"><strong>현장에서 보면</strong><p>…</p></div>`
- **주의 박스** (업체를 불러야 하는 경우·안전, 필요할 때 1개):
  `<div class="mi-warn"><strong>이럴 땐 업체에</strong><p>…</p></div>`
- **강조**: 굵게는 글당 핵심 문장 3~5개만. 문단 전체를 굵게 하지 않는다
- **쿠팡 후보**: 본문 흐름 안 해당 위치에 한 줄로 `[쿠팡 후보: 제품군]`

박스는 워드프레스 "코드 편집기"나 "사용자정의 HTML" 블록에 그대로 붙여넣을 수 있는 형태로 쓴다.

### 참고: 사이트 추가 CSS (GeneratePress → 외모 → 사용자 정의하기 → 추가 CSS, 한 번만)
```css
.entry-content .wp-block-table{border-radius:14px;overflow:hidden;background:#f6f8f7}
.entry-content .wp-block-table table{border-collapse:collapse;width:100%}
.entry-content .wp-block-table th{background:#2f6b57;color:#fff;border:0;padding:12px 14px;text-align:left}
.entry-content .wp-block-table td{border:0;padding:12px 14px}
.entry-content .wp-block-table tbody tr:nth-child(even) td{background:#fff}
.entry-content .mi-summary{background:#edf4f1;border-radius:14px;padding:18px 20px}
.entry-content .mi-tip{background:#fbf3e4;border-radius:14px;padding:16px 18px}
.entry-content .mi-warn{background:#fbeeec;border-radius:14px;padding:16px 18px}
.entry-content h2{border-top:1px solid #e3e9e6;padding-top:18px;margin-top:40px}
.entry-content h3{color:#21503f}
```

## 5. 이미지
- 실사진이 있으면 최우선 사용 `[사진: 설명]`
- 없으면 `[이미지 자리: 무엇을 그릴지]` (구조도, 규격표, 판단 순서도). 설명용으로만, 실사진처럼 보이게 하지 않는다
- 타 사이트·제조사 이미지 사용 금지. 모든 이미지에 키워드가 자연스럽게 들어간 alt 텍스트 작성

## 6. 안전·신뢰
- 전기·가스·고소 작업: 안전 절차와 전문가 경계 명시
- 가격·통계: 출처 링크를 달거나 "2026년 ○월 기준, 조건에 따라 다름" 표기. 근거 없는 수치 금지
- 사실 확인이 필요한 규격·기준은 웹에서 확인 후 쓰고, 확인 못 한 것은 쓰지 않는다

## 7. 자동 검사·수정
**Claude Blog(`/blog`)를 쓸 수 있는 환경(Claude Code)이면 작성 직후 반드시 아래를 실행한다.**
1. 초안을 `drafts/myinfobay/<영문슬러그>.md` 파일로 저장한다
2. `/blog analyze drafts/myinfobay/<영문슬러그>.md` 실행
3. 90점 미만이면 지적 사항을 이 스킬의 규칙 안에서 직접 고친 뒤 다시 analyze. **최대 3회**까지 반복. 고칠 때 한국어·해요체·쿠팡 링크 금지·용어 확인·글 꾸미기 형식 등 이 스킬 규칙을 바꾸지 않는다
4. `/blog factcheck` 실행 → 출처와 맞지 않거나 확인 불가로 나온 수치·주장은 고치거나 삭제
5. 최종 점수와 수정 내역을 출력에 적는다. 3회 후에도 90점 미만이면 남은 문제를 정리해 사용자에게 보고한다

Claude Blog를 쓸 수 없는 환경(Claude 앱 대화 등)이면 아래 자가 점검표로 스스로 확인·수정하고 결과를 출력한다.
- [ ] 결론이 첫 3문장 안에 있고 3줄 요약 박스가 있다
- [ ] 본문에 H1이 없고, H2마다 첫 문단이 단독으로 답이 된다
- [ ] 비교표가 있다
- [ ] 현장 팁 박스가 있다
- [ ] 근거 없는 수치·과장 표현이 없고, 인용한 기준은 출처가 있다
- [ ] 쿠팡 링크·광고 유도 문구가 없다 (승인 전)
- [ ] 네이버 블로그 글과 겹치는 문장이 없다
- [ ] 모든 부품·자재 이름이 0-1단계에서 확인한 소비자 용어다

발행 후 URL이 생기면 `/seo page <URL>`로 한 번 더 점검하라고 출력 끝에 안내한다.

## 8. 사이트 템플릿 확인 (사용자 요청사항)
출력 맨 끝에, 아래 사이트 쪽 요소가 세팅됐는지 사용자에게 한 줄로 확인한다. 사용자가 모두 끝났다고 답한 적이 있으면 더 묻지 않는다.
- 글 끝 작성자 박스 (우드엔조이 소개 + 소개 페이지 링크)
- 글 상단 업데이트(수정) 날짜 표시
- 글 끝 출처 표시 자리
- 4단계의 추가 CSS 적용

## 9. 출력 형식
1. 메인 키워드 + 보조 키워드 3~5개
1-1. 용어 근거: 소비자 용어 / 업계 용어 / 확인 못 해서 뺀 용어
2. 제목 3안 + 추천 1개와 이유
3. 영문 슬러그
4. 메타 디스크립션 (공백 포함 약 120~150자, 키워드 + 클릭 이유)
5. 본문 (H2·H3 마크다운 + 4단계 박스 HTML. 워드프레스에 붙여넣기 쉬운 형태)
6. 이미지 목록 + alt 텍스트
7. 내부 링크 후보, `[쿠팡 후보]` 목록
8. 검사 결과 (`/blog analyze` 점수·수정 내역·factcheck 결과, 또는 자가 점검표 결과)
9. 사이트 템플릿 확인 한 줄 (8단계)
